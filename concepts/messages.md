In LangChain, communication with Chat Models is structured around a unified schema of **Message objects**. Instead of passing raw strings, you pass a list of these message objects, which map directly to the roles (like system, user, or assistant) expected by underlying APIs like OpenAI, Anthropic, or Anthropic.

## The Core Message Types

All LangChain messages inherit from `BaseMessage` and possess two main properties:

* `content`: The text content of the message (or a list of dictionaries for multimodal inputs like images).
* `additional_kwargs`: A dictionary for provider-specific data (e.g., tool call definitions from OpenAI).

### 1. `SystemMessage`

* **Purpose:** Sets the behavior, tone, constraints, or persona of the AI model. It is typically passed at the very beginning of a conversation.
* **Underlying Role:** `system`

### 2. `HumanMessage`

* **Purpose:** Represents a message sent by a human user interacting with the model.
* **Underlying Role:** `user`

### 3. `AIMessage`

* **Purpose:** Represents a message returned *from* the AI model. It can contain text, or specific fields like `tool_calls` if the model decided to invoke an external function.
* **Underlying Role:** `assistant`

### 4. `ToolMessage`

* **Purpose:** Used to pass the *results* of a tool execution back to the model. It **must** include a `tool_call_id` that matches the ID generated by the preceding `AIMessage`.
* **Underlying Role:** `tool`

### 5. `ChatMessage`

* **Purpose:** A fallback or generic message type. If a specific provider uses a non-standard role (e.g., "function" in older APIs or custom roles), you can use `ChatMessage(role="your-custom-role", content="...")`.

## Code Implementation

```python
from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage,
    ToolMessage,
    ChatMessage
)
from langchain_openai import ChatOpenAI

# 1. Initialize the model
model = ChatOpenAI(model="gpt-4o", temperature=0)

# 2. Construct a standard conversation history
messages = [
    SystemMessage(content="You are a strict data engineering assistant who answers concisely."),
    HumanMessage(content="What is the difference between CloudFiles and standard directory listing in Databricks?")
]

# 3. Invoke the model (returns an AIMessage)
ai_response = model.invoke(messages)

print("Type:", type(ai_response))
print("Content:", ai_response.content)

```

### Simulating a Tool Call Sequence

When working with tools (especially crucial in LangGraph), the message flow requires `AIMessage` and `ToolMessage` to tightly pair their IDs.

```python
# Imagine the user asked to look up a record, and the model decided to call a tool
messages_with_tool = [
    SystemMessage(content="You have access to a database lookup tool."),
    HumanMessage(content="Look up status for job_id_992."),
    
    # The AI responds requesting a tool execution
    AIMessage(
        content="",
        tool_calls=[{
            "name": "db_lookup",
            "args": {"job_id": "job_id_992"},
            "id": "call_abcd123"  # Unique ID generated by the LLM
        }]
    ),
    
    # You execute the tool in your python code, and feed the result back via ToolMessage
    ToolMessage(
        content="{'status': 'FAILED', 'error': 'Out of Memory'}",
        tool_call_id="call_abcd123"  # Must match the AIMessage tool_call ID exactly
    )
]

# Ask the model to generate its final answer based on the tool result
final_response = model.invoke(messages_with_tool)
print(final_response.content)

```

## The Shorthand Alternative: Role-Based Tuples

While using explicit classes like `HumanMessage` is robust and preferred in complex LangGraph state objects, LangChain allows a highly popular shorthand notation using **tuples** when passing lists directly to models or prompt templates.

LangChain automatically coerces these tuples into their respective message classes under the hood:

```python
# This syntax is completely interchangeable with the class-based approach for initialization
messages_shorthand = [
    ("system", "You are a helpful physics professor."),
    ("user", "Explain quantum entanglement in one sentence."),
]

response = model.invoke(messages_shorthand)

```

* `"system"` $\rightarrow$ `SystemMessage`
* `"user"` or `"human"` $\rightarrow$ `HumanMessage`
* `"assistant"` or `"ai"` $\rightarrow$ `AIMessage`
